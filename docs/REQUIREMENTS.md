## 1. 产品定位与目标

一个 **7×24 的 AI 个人助理**，帮用户把零散、跳跃、混杂的日常需求，沉淀为可追踪、可推进、有进展状态的事项，并像真正的助理一样：理解用户、主动办事、适时提醒、清晰汇报。

**核心目标：**

1. **降低表达负担**：用户只需"说一句"（语音/文字/截图），无需组织语言、无需分类。
2. **像人一样办事**：理解上下文、串联关联事项、主动补全，而不是被动应答。
3. **让进展可见**：用户随时知道"每件事办到哪了、卡在谁那里、下一步是什么"。
4. **适度主动，不过度打扰**：该提醒时提醒，该静默时静默。

---

## 2. 目标用户与核心场景

**用户**：有家庭的上班族（示例用户"小包爸爸"），生活多线程——育儿、健康、购物、出行、工作、社交、家庭。

**核心场景**（来自用户真实需求，作为内置用例基准）：

| 领域 | 典型需求 |
|---|---|
| 购物 | 补货加购+用券、多平台比价、价格监控、生成菜单 |
| 育儿 | 疫苗预约、定期量身高体重、网课提醒、孩子忌口/口味 |
| 出行 | 订票（飞机/动卧）、接站攻略、停车、餐厅预订 |
| 健康 | 肩颈拉伸提醒、就医焦虑处理 |
| 工作 | 会议提醒、写报告提醒、会议记录 |
| 社交/家庭 | 生日会、寄物品、家人行程 |

## 3. 功能需求

### 3.1 输入与捕获

- **R1** 支持语音、文字、截图、聊天记录等多形式输入，统一落入收件箱。
- **R2** 捕获零摩擦：输入时不要求用户提供结构/分类，结构化由系统后台完成。

### 3.2 结构化与管理

- **R3** 把零散输入拆解为「事件卡（Occasion）→ 子事项（Item）」两级：用户心智里的"一件事"是一张事件卡，下面挂若干子步骤。
- **R4** 自动识别事项类型：一次性 / 周期 / 监控 / 条件触发。
- **R5** 自动归类主题：购物、育儿、健康、出行、工作、社交、家庭等；支持用户自定义/变更任务主题。
- **R6** 相关性合并：时间/空间/人物/目的连续的需求（如"接奶奶"+"路上吃饭"+"记得充电"）归到同一张事件卡；独立需求另建新卡。

### 3.3 状态与进展

- **R7 状态与回执区分**：内部仍保留七态：待启动、运行中、需您协助、已完成、暂停、取消、异常。每张卡只表达一个任务级状态；“已创建”是创建事件的历史回执标签，不新增第八种执行状态。历史创建卡保持“已创建”，后续执行不会回写它。AI 在管、待您处理、待归档用于聚合；归档不属于任务执行状态。状态配色统一按 U11、U12 和 4.20 执行。
- **R8** 「等待外部」（等价格/等回电/等物流）不作为顶层状态，降级为「运行中」的子标注（如"运行中 · 监控中"）。
- **R9** 每个任务要有简要的**关键描述**（一句话）：交代「已做到什么 + 接下来打算怎么做」，让用户一眼感知现状与计划（例："攻略已做好，正在蹲活动降价"；"就差你确认下单"）。

### 3.4 长期记忆与关联

- **R10** 长期记住实体：家人（关系、口味、忌口、健康档案）、账户（各电商历史订单偏好）、地点（家、常去位置）等。
- **R11** 长期记住偏好/习惯（常买什么、口味、出行习惯等），跨会话持续累积。
- **R12** 关联推理：能从一条需求串联相关上下文（"牛奶没了"→历史订单→孩子口味→忌辣→生成菜单）。
- **R13** 跨会话指代消解：隔了几天、中间穿插其他话题后提到的"接奶奶那天…"，仍能接回原有事件卡。

### 3.5 主动服务与提醒

- **R14** 主动式服务：基于时间/事件/上下文主动准备（查好、比好、备选列好），而非被动等待。
- **R15** 主动不越权：下单、订票、发消息、预约等动作，默认先确认再执行。用户明确交代“加入购物车”时，整理清单、核对优惠与加购均属于已授权范围，不再次要求确认同一个加购动作；下单、支付仍由用户确认。遇缺货替换、预算变更等超出原授权的决策再询问。
- **R16** 打扰分级，至少四档：
  - 紧急且需决策 → 实时提醒
  - 时间敏感 → 到点提醒
  - 低优先级/持续 → 静默执行，进每日简报
  - 固定周期 → 自动触发 + 结果汇报
- **R17** 打扰阈值可配置，且可被反馈训练（"以后这种不用问我"→降级）。

### 3.6 外部工具与集成

- **R18** 接入电商（盒马/小象/山姆/麦德龙/京东等）：查历史订单、加购、比价、用券、监控价格。
- **R19** 接入内容平台（如小红书）：搜索好物/攻略，返回结论并附原帖链接，注意信息时效。
- **R20** 接入出行（12306/航旅/地图）：查票、导航、接站停车位置。
- **R21** 接入通讯：拨打电话（如给社区医院、餐厅确认）。
- **R22** 接入办公：日历、会议室、会议记录。

### 3.7 汇报与简报

- **R23** 每日/定期简报，静默汇总进展，不逐条打扰。

### 3.8 交互归口与附件

- **R24 交互归口**：任务执行过程中需要与用户交互时，统一由总助理出面，子代理不直接与用户对话；子代理需要用户输入时回传给总助理，由总助理决定是否询问、如何合并。
- **R25 附件·上传**：主入口支持用户上传附件（截图、图片、文档、PDF、语音），附件关联到对应消息与事项。
- **R26 附件·产出**：子任务执行过程中可生成附件（菜单、比价表、攻略截图、会议纪要等），由总助理带回并关联到事项，供用户查看/下载。
- **R27 附件·呈现**：附件统一呈现——对话流可预览、事项详情有附件区、任务执行详情列出产出物。

### 3.9 任务完成与执行详情

- **R28 任务完成卡片**：任务完成后，主会话新增更新后的精简任务卡，简要说明结论，可引用用户原话。点击进入同一任务概览，展示当前最新情况；历史创建卡保留当时快照，不静默改写。
- **R29 子任务执行时间**：规划执行表逐步展示思路、已完成步骤的结果和起止时间；未完成步骤可显示预计耗时。每行只用 ✓ / — / ○ 表示完成 / 进行 / 待开始，不再叠加文字状态标签。

### 3.10 任务类型、未来实例与需用户参与

- **R30 类型与标识分离**：数据层区分一次性、周期、监控、条件触发等类型；卡片不再展示一次性标识。只有真正按周期重复执行的任务显示循环图标，持续监控本身不自动等于周期任务。
- **R31 延续性任务呈现未来实例**：延续性任务由「主体 + 未来实例」组成。主体任务常驻；"下一次要发生的时间点"（周期到点、监控侦测到的大促/活动、到点提醒）作为独立实例浮出，状态为「待启动」，到点触发后转为相应状态。
  - 例：蒸烤箱比价前天开始、今晚完成第一版方案（主体 · 运行中）；侦测到"两天后有大促" → 浮出待启动实例「两天后 · 大促蹲价/下单」。
- **R32 本人参与边界**：只有确实需要线下到场或线下亲自完成的事项，才显示小人图标。登录、授权、确认信息、下单、支付和反馈属于“需您协助”，不因需要用户操作而判为线下。两种条件可同时成立。

### 3.11 完成与归档闭环

- **R33 需用户参与事项的完成认定**：进入「等你」后，给用户一个"已完成"按钮——查看消息/卡片时即可点；不点则默认 **2 天后自动关闭**（转为完成）。
- **R34 归档闭环**：完成/取消的事项不立即消失，先进入「待归档」暂存；积攒一批后由 AI 汇总确认一次（"这 N 件事要归档吗？"），用户确认没问题即归档。

---

### 3.12 非阻塞对话、任务回执与状态边界（2026-10-14 新增）

- **R35 输入分流**：接收输入后，后台立即判断为直接回复、新建任务或更新已有任务。即时问答不创建任务；需要持续推进的需求才建卡。判断与执行不阻塞继续输入或布置其他任务。
- **R36 创建回执**：新任务建立后，小天简短回应并展示“已创建”卡片，用户可以立即继续聊天或交代其他事。历史创建卡固定；工作台和详情显示任务当前状态。新建与更新已有任务须区分，补充旧任务不能伪装为再次创建。
- **R37 任务目标边界**：状态描述 AI 承诺的任务目标。目标为“加购”时，已加购并告知用户即完成，支付是结果中的后续交接，不把已完成的加购任务继续标成需您协助。目标包含下单时，付款或下单审批未完成才可阻塞任务。
- **R38 待确认判定**：只有缺少关键资料或必须由用户决定、AI 无法继续推进时才进入需您协助。等待外部回电、检索、优惠核验等仍为运行中。非阻塞交接与必答确认需区分。
- **R39 确认记录**：每次确认保存问题、提出时间、是否阻塞、选项、用户答复及答复时间。没有确认信息时明确显示“无”；已答问题保留，不被覆盖。
- **R40 结果区域**：任务未完成时保持空白，不预填计划或预测结果。完成后放结论、金额、下一步和产出附件；异常、取消、暂停则在同一区域解释原因、已完成部分和后续安排。
- **R41 状态事件回执**：完成、发起确认、收到确认答复、暂停、取消、恢复和补充信息都追加会话消息与任务卡快照。点击任何历史快照进入同一个 task_id 的当前概览。

### 3.13 示例闭环：给小包买菜（当日定稿）

| 顺序 | 对话／事件 | 会话中的卡片与状态 |
|---|---|---|
| 1 | 用户：“家里牛奶和小包吃的菜没有了，参考常买的帮我加购，优惠帮我用上。” | 小天简短接单，给“给小包买菜 · 已创建”卡，默认底色。 |
| 2 | 用户继续问“你可以同时帮我处理别的事吗？”；小天回应可以，买菜继续处理。 | 不重复建卡；体现执行不阻塞聊天。 |
| 3 | 执行中发现常买牛奶缺货，询问能否换同品牌 950mL、蔬菜备几天。 | 新增“需您协助”卡，淡蓝底；之前的创建卡不变。 |
| 4 | 用户补充：“可以换同品牌 950mL 的，蔬菜按两天的量准备，先加购物车，不要付款。” | 记录答复与时间；小天回应继续核对优惠并加购，不重复创建任务。 |
| 5 | 过一会儿执行完成，示例用“3 分钟后”分隔。 | 新增“已完成”卡，浅绿底，说明 5 件商品、优惠后 ¥105、未下单未付款。 |

三张卡是同一任务的不同历史快照，点击任意一张都查看当前最新详情。详情保留原始需求及附件、执行步骤、规格与用量确认、答复时间、结果及购物车图片。确认提出时的问题仍保留，即使当前已答复。

“已完成”针对加购目标；支付属于后续交接。未确认支付时仍可带 Help 提示，但不能把加购完成卡改回“需您协助”。示例金额、商品和执行均为模拟。


## 4. UI / 交互需求（最终规则）

### 4.1 总体设计原则

- **U1 简约、清晰、有设计感、使用友好**（用户明确的总体要求）。
- **U2 界面要体现"助理在帮我办事"，而不是"我在管理任务清单"**——用户是被服务的人，不是任务管理员。

### 4.2 入口页

- **U3 主会话“吩咐我”**：首页直接展示对话流，第一句为“有什么事，直接吩咐我就好。”；输入框默认收起，主要入口为可点击的语音按钮。移除“小天一直在”“说完，就交给我”“任务交代 · 情景演示”等开场区块。
- **U4** 入口页视觉极简，复杂结构不前置；可适度展示助理的主动提示作为入口。
- **U5 双页面导航**：“吩咐我”和“小天工作台”是两个主页面。对话页左滑进入工作台，工作台右滑返回；页面顶部也支持相同手势。移除顶部与底部双按钮导航，以右侧贴边椭圆切页条补充点击导航，详见 4.18。

### 4.3 小天工作台（时间表与任务视图）

- **U6 工作台定位**：以事情的时间表为主要首屏，合并原总览、时间轴、事件轴和按主题查看的入口；下方保留主题任务详情与主动关心，不单独保留重复的时间轴小页面。服务成果统计默认收起，不占据顶部主要空间。
- **U7 量化体现生活中的服务与成效**：陪伴天数、累计照料任务、省时估算、省钱；以采购、退货、订票、重要提醒、长期任务的数量补充。估算与实绩须区分，详情报告提供依据。
- **U8 主动关心入口**：置于时间表下方的第二个 Tab，与“全部主题”并列。默认选中“全部主题”；主动关心不再作为主题列表第一项。建议未采纳前不作为任务执行。
- **U9 体现原始会话与当前任务的关联**：每个事项/结果可追溯到用户的那句原始输入（如原话引用）。
- **U23 工作台 = 助理的任务视图**：展示助理正在做、已完成、即将要做的事（而非用户的待办清单）；每条任务区分「一次性 / 延续性」。延续性任务**主体常驻**（运行中），同时把"下一次要发生的时间点"（未来实例）以「待启动」状态一并浮出。
- **U24 需用户参与标识**：需用户亲自参与的事项（线下参会、接人、量身高、本人到场等），在卡片/条目上加「小人儿」图标示意，与"AI 代办"一眼区分，不依赖读文字。

### 4.4 关键信息与结果

- **U10 关键信息、结果要突出**，不埋在大段文字里。例如比价场景，用户最关心"当前最优方案的价钱是多少"，应作为最醒目的信息呈现（大字/高亮），而非在描述里找。

### 4.5 状态可视化

- **U11 状态文字与四色分组**：保留小号、浅色的状态文字，任务标题附近即可看到。已创建／待启动／进行中共用默认底色；已完成用浅绿；需您协助用淡蓝；取消／暂停／异常共用浅灰。状态不能只靠颜色分辨，不再使用七种背景各表一态。
- **U12 视觉优先级**：只有完成与需要用户协助两类使用明确色彩提示；其余保持克制。取消、暂停、异常依靠文字说明区别，不再分别使用紫色、红色等多套配色。所有任务卡共用规则，与右侧暖米色用户消息区别开。

### 4.6 事项详情

- **U13** 点击任务卡进入「任务概览页」，固定顺序为：原始需求（产生时间、原文折叠、输入附件）→ 规划与执行表 → 用户待确认的信息及答复历史 → 任务结果与产出附件 → 完整执行详情链接 → 暂停、取消、补充信息。

### 4.7 任务执行详情

- **U14** 从事项可跳转到具体的任务页面，查看执行进展：子任务目标、执行流程（思考、工具调用、观察等）。
- **U15 约束** 该任务执行页面**直接复用 dsh 的任务页面，不单独设计**。

### 4.8 主题

- **U16** 内置多种风格主题（如：温馨、商务、童趣等），可切换。

### 4.9 内置用例

- **U17** 内置用例要全面，覆盖第 2 节各领域场景，便于演示与验收。

### 4.10 交互载体与附件

- **U18 交互归口**：提问、确认、汇报统一由总助理在主会话承接；每次完成、发起确认、确认答复、暂停、取消、恢复或补充信息，都在主会话新增更新卡。详情保存原始需求、历次补充和确认记录；同一任务不另建重复卡。
- **U19 附件上传**：主入口输入区提供附件上传入口（截图/图片/文档/PDF/语音），附件关联到消息与事项。
- **U20 附件呈现**：附件在对话流可预览；事项详情页有附件区；任务执行详情页列出产出物。

### 4.11 边滑边处理与完成反馈

- **U21 边滑边说**：语音按钮短按开始，再按结束，不要求一直按住。按钮原位变为工作状态；点击开始时展开底部紧凑转写框，不弹模态窗口，用户仍可滑动、切页。长按属于拖动按钮位置，不能误启动语音。

- **U31 历史回执稳定**：主会话按事件追加静态快照。创建、需您协助、完成等卡片各自保留当时的标题、状态、摘要和事件时间，不因任务继续推进而改写。点击所有同任务的历史卡均以同一 task_id 打开当前任务详情。


### 4.13 生活化服务成果与照料报告

本节保留服务量与效果的量化要求；展示位置以本版工作台“统计默认收起”为准。

- **U32 收起的服务成果**：工作台时间表下保留“陪伴您的这些日子”等可展开统计入口，默认收起。展开后简洁表达陪伴 XX 天、累计照料 XX 项事、预估节约 XX 小时和省下 XX 元；未知数据展示“待核实”。不恢复顶部大统计区。
- **U33 生活分类次数**：简洁展示日常采购、退货、订票、重要提醒、一起做过的长期任务。一次服务只计一次，卡片更新、子步骤、未来实例不反复累加。
- **U34 照料报告入口**：在收起的服务统计区内提供报告链接，包含统计区间、分类数据、需求观察、建议、重要提醒与估算依据。观察基于已知任务，不把推测当确定偏好。
- **R42 统计定义**：陪伴天数从服务开始日期按用户时区计算；累计照料按被接受的任务主体去重，含进行中及历史，不含未采纳建议；完成量不计取消或未核实自动关闭。各分类可与其他统计存在不同口径，报告中明确说明。
- **R43 省时省钱**：省时为有依据的人工耗时基准估算，不等于 AI 运行时长。省钱使用同规格、同服务条件的比较基准与已成交凭证；退款金额不作为节省金额，未支付购物车优惠只可显示潜在优惠。没有可核实依据则不计入实际节省。
- **R44 Demo 标注**：示例历史、服务次数、金额和省时显著标为演示。正式报告需下钻真实服务记录；原型可用有口径说明的历史汇总，并明确尚未接入账号。

### 4.14 当前照看、重点汇报与折叠主题

- **U35 当前总况**：在统计／主题汇总中表达“正在为您照看 XX 项事，其中 XX 件待您处理”，避免另加占据首屏的大型总况模块。照看包含非终态主体及已完成但仍有交接的事项；无交接的历史已了结任务不计入正在照看。
- **U36 优先事项**：优先把需用户确认的任务排到主题内部前方，并用一句话说明需要做什么。必要汇报最多突出 3 项，不能挤占主要时间表；点开仍进入原任务详情。
- **U37 全部主题折叠**：默认选中“全部主题”，各场景／主题初始折叠；支持单独展开和一键全部展开／收起。折叠条显示主题、任务数、AI 在管、待您处理、待归档，暂停单列。已操作后的折叠状态可在当前浏览器保留；最新规则不再要求切换协助筛选后强制展开。
- **R45 聚合边界**：AI 在管不含暂停、终态及需要用户介入的事项；待您处理含阻塞确认、需本人参与及尚未答复的非阻塞交接。AI 加购完成仍显示“已完成”，用户支付提示不会使其回到运行中。存在未答复交接时先不放进批量归档，用户确认已支付或暂不购买后可归档。
- **U38 主题内排序**：待用户确认／处理的任务置顶；组内按创建时间从新到旧；其余任务同样按创建时间倒序。更新原任务不改创建顺序。
- **U39 高密度一致性**：会话与主题卡使用统一组件，批量卡仅调整为组内紧凑布局；日历卡因空间采用三行结构，但遵循相同状态文字与配色。标题、状态、最新进展／结果必须清晰；完整信息由详情承接。

### 4.15 主动关心：建议到采纳的完整闭环

- **U40 主动关心 Tab**：工作台下方第二个 Tab 为“主动关心”，默认不选中。进入后显示建议总数与已采纳数、可勾选建议、简短缘由和执行思路；无需先展开一个同名主题。保留采纳所选与全部采纳。
- **R46 采纳行为**：支持多选采纳与全部采纳。未采纳建议不计任务、不执行；采纳后创建或关联实际任务，保存建议来源、用户确认时间与归属主题，重复采纳不得重复建卡。
- **U41 合并采纳回执**：一次采纳在主会话合并为一条“您已采纳推荐任务……”和总助理回应，附同一批任务卡，不逐条发送消息。用户仍留在当前工作台，可以继续浏览。

### 4.16 全局免长按语音、整理确认与暂存

- **U42 免长按语音入口**：两个主页面与任务详情可使用麦克风。短按开始，再按“结束”；工作状态原位可见，仍可滚动和切页。长按约 360 毫秒后可拖动位置，松开不触发语音动作。正式识别保留连续 60 秒无声自动结束要求，当前模拟 Demo 不据此宣称已完成真实静音检测。
- **U43 紧凑转写框**：默认隐藏；点击语音开始才展开固定高度的小输入框，长文本在框内滚动，支持手动展开／缩小／收起。当前基准高度约 40px，展开约 136px，可按屏幕适配。语音按钮平时标“吩咐我”，工作时显示动态状态和“结束”；不弹提示框，不前置连接失败提醒。当前 Demo 用模拟文字逐步填入，不请求真实麦克风权限。
- **R48 语音整理**：识别结束后去除冗余、分成独立指示，保留原始转写，供用户修订。相关指示关联已有任务；新需求新建；有歧义时先确认，不因相邻任务可见而擅自关联。Demo 用可编辑分句演示，不代表已接入语义模型。
- **U44 确认后分流**：“确认，暂存”或“确认，发给主会话”。暂存不执行、不创建任务；内容通过右侧浮动便笺图标与数量提示，在当前页面覆盖展开。
- **R49 暂存生命周期**：保存时间、整理后的指示、上下文与原文；支持查看、修改、删除、发送；刷新后保留。发送成功后移除对应暂存批次，防止重复提交。
- **U45 主会话承接**：发送后主会话显示“查看进展后，我的安排：……”及“收到，正在为您处理”，再集中呈现创建或更新的任务卡；保持非阻塞。
- **U46 批量卡片组**：一个任务用普通卡；同次涉及两个及以上不同任务时，合并为一个整体卡片组，显示统一标题、任务数和简短状态汇总。默认展开，组内双列紧凑卡片，可一键收起／展开。组内高度受限，内容多时原生纵向滚动；每项可点详情，后台更新应保留组的展开状态和滚动位置。废止“1–3 张逐张展示、超过 3 张仅先露 2 张”的旧方案。

### 4.17 时间轴语义与图标

- **U47 时间轴定位**：横向日期、纵向上午／下午／晚上，使用任务实际启动时间或预计启动时间，不得拿创建时间、需用／截止时间代替。未明确启动时间归入独立折叠区。
- **U48 默认日期与溢出**：进入工作台时定位用户所在时区的今天，并只显示当天一列，清楚标注“今天”；可横滑看其他日期、双指缩放。去掉日期范围筛选和加减缩放按钮。各时段按内容自适应，任务全量展开，不在时段内部设置滚动窗口；内容多时允许整张表变高，由页面纵向滚动浏览，不再硬性限制表高不超过一屏。
- **U49 按条件显示标识**：Help 保留文字，并紧跟极简动作，如“请您登录／请您下单／请您支付／请您反馈／请您确认”。周期用循环图标，线下用小人图标；不重复叠加同义文字，不符合条件则不显示。三者彼此独立，允许同一任务全部出现；提供可点击的图标说明与无障碍名称。
- **R50 周期实例**：周期任务的每次发生分别按日期显示实例，不只展示最近一次。例：每天 19:00 的“提醒去游泳”在多天晚上均出现；未到时为待启动，模拟发出提醒后该次为已完成，带周期与线下图标。提醒完成不代表已到场或运动已完成；监控主体本身不反复铺满日历。


### 4.18 品牌、主页面与切页入口

- **U50 品牌与文案**：产品名“小天”；slogan 为“人生归你，琐碎归我，愿你自在每一天”。对话助手署名仅“小天”，不再写“拾伴 · 总助理”。产品名称和 slogan 比正文醒目，字号适当放大、顶部留白缩小，保留手机安全区；不得为了放大而挤占过多有效内容。
- **U51 顶部呈现**：对话页顶部为“小天”及 slogan，工作台顶部仅写“小天工作台”。移除顶部“演示”“包爸”等入口，不显示顶部或底部“吩咐我／工作台”双导航按钮。移除多余介绍语，但保留一条简短对话引导。移除顶部演示标签不等于宣称接入真实执行，模拟性质在相关结果／报告或必要说明中保留。
- **U52 手势切页**：从“吩咐我”左滑进入工作台，从工作台右滑返回；标题和顶部空白区域也响应。普通对话卡片上可以发起页面滑动；日历横滑／缩放、批量卡组内滚动、输入编辑和浮动控件拖动不被页面切换劫持。轻点、上下滑动和多指操作不能误切页；成功滑动后不误触卡片点击。
- **U53 右侧贴边切页条**：采用横向椭圆长条，默认收起在右边，只露少量边缘与展开提示（当前基准约 22px）。第一次点击只展开，第二次点击目标页面才跳转。对话页目标为“工作台”，工作台页目标为“吩咐我”；点击条外或切页后收起。它替代此前的无外圈箭头／返回图标方案。长按可上下调整位置，松开仍贴右边，记住位置。
- **U54 浮动控件**：语音按钮与切页条相邻但不重叠，不盖住常用发送操作。语音按钮长按可拖到页面其他位置，切页条保持右侧吸附。拖动不触发原本点击动作；短按仍执行语音／展开／跳转。屏幕尺寸改变或输入区展开后，控件须在可操作区域内，不能拖出屏幕后无法找回。位置按当前浏览器记忆。

### 4.19 对话角色区分与简短引用

- **U55 用户消息**：右对齐暖米色气泡，深色文字；短消息随内容收窄，长消息有宽度上限与自动换行。通过位置、底色和留白与小天回复区分，不再整页都用绿色。
- **U56 小天回复**：左对齐，轻量“小天”署名，正文自然展开；任务卡是回复中的独立信息单元。避免过重的双边聊天气泡和重复头像挤占宽度。
- **U57 引用规格**：“您的吩咐”作为短标签，放在本次对应回复内容最上方、正文和卡片之前；浅色细竖线、浅色小字、单行、最多 28 个字符（含省略号），窄屏继续省略。不再使用“关于您的交代”等长引导语，不重复大段原文；完整原话始终可在详情找到。
- **R51 回执不覆盖**：创建、需协助、完成和后续调整各自形成带事件时间的快照。历史内容以快照为准，不从实时任务重新推导成新状态；点击仍指向同一任务最新详情。此规则适用于所有任务和批量回执，不只购物示例。

### 4.20 全部任务卡的统一规范

同一语义在单张会话卡、批量卡、主题卡、示例卡和日历卡中保持一致。日历和批量布局可以更紧凑，但不能另造状态名称或多一套状态颜色。

| 状态分组 | 覆盖状态／标签 | 背景规则 | 识别方式 |
|---|---|---|---|
| 常规 | 已创建、待启动、进行中 | 统一默认浅底色，不单独高亮 | 小号状态文字；已创建是回执事件标签 |
| 已完成 | 已完成 | 低饱和浅绿 | 完成文字及简短结果 |
| 需要用户 | 需您协助 | 低饱和淡蓝，与用户米色消息区分 | 明确状态及下一步动作 |
| 中止／问题 | 取消、暂停、异常 | 三者统一浅灰 | 各自状态文字、详情中的原因与后续安排 |

- **U58 文案与配色约束**：统一写“需您协助”，不使用“虚拟协助”“需用户协助”。常规运行状态在当前 Demo 中存在“运行中／在干活”措辞，对应同一运行语义与默认底色；不因此新增状态。已创建不得替代工作台的实时执行状态。取消／暂停／异常不再各用独立彩色背景。
- **U59 组件结构**：标题为第一层，状态用较小、较浅文字放在标题后或同一标题区；下方一至两行最新进展／结果，再放必要场景、图标、时间与详情入口。不得在摘要、状态和标识中反复写同一件事。
- **U60 批量卡布局**：同批多任务共用一个容器、标题、任务数量与状态汇总，默认展开；展开区域为双列小卡（过窄屏可适配），统一间距与底色规则。收起后只保留总况和简短摘要。展开高度建议约半屏，组内原生纵向滚动；不能压缩各行导致内容不可读或“滑不动”。支持在卡面起滑；拖动滚动不打开详情。组内滚动与日历时段“不设内滚动”是不同规则。
- **U61 详情一致**：点击任意普通卡、历史卡、批量卡、日历卡均进入对应 task_id 的最新任务详情。保留原需求、补充、确认记录、步骤、结果、附件及完整执行详情入口，不能因为首页精简而删除。

### 4.21 工作台表格、筛选与下方内容

- **U62 页面层级**：顶部“小天工作台”→ 时间表（内部小筛选）→ 默认收起的服务统计／报告入口 → “全部主题／主动关心”双 Tab → 对应内容及归档入口。时间表为首要内容；保留下方任务详情与主题信息。
- **U63 表内筛选**：只保留“全部、需您确认、需您在场”三个紧凑按钮，放在时间表内部上方，默认“全部”。不再独立占一行大按钮，不恢复旧时间范围选择与加减控件。
- **R52 筛选边界**：“需您确认”涵盖当前待用户登录、授权、确认资料、下单、支付、反馈等协助，以及确实需要用户介入的异常；已完成任务仍有未答复支付交接时也应出现。“需您在场”只含尚需真实线下到场／完成的事项；线上操作不算线下。两者可交叉，不强制互斥。已完成提醒不得自动视作线下事项已完成。
- **U64 时间表三行卡片**：第一行任务名称和小号浅色状态；第二行仅在需协助时显示 Help 与具体动作；第三行是时间、循环图标和小人图标。Help、周期、线下逐项判断，不符合不显示；时间和两类图标同一行。除必要换行外控制卡片占高。
- **U65 今天与自适应**：默认视野仅覆盖当天；用日期及“今天”标记。日期按用户时区（当前用例为 Asia/Shanghai）计算，演示执行时钟不能使今天定位偏移。首次打开及重新进入工作台时定位今天；手动横滑后允许浏览其他日期。上午／下午／晚上高度由内容决定，少任务时紧凑、多任务时完整展开，通过页面滚动看全；不再设置每个时段的内部滚动条，也不保留表格必须一屏容纳的上限。
- **R53 标签验收场景**：登录邮箱／购物支付只带 Help，不带线下；线下会议仅确需到场时带小人；到场前还需确认地点可同时带 Help 与小人；每天 19:00 提醒去游泳带循环与小人，若另有必要确认也可带 Help。持续盯价格但没有固定重复节奏时，不自动展示循环标识。

### 4.22 语音与输入的当前演示范围

- **U66 当前 Demo**：点击语音后按钮显示工作态，固定高度输入框展开，模拟文字逐步出现；可以继续浏览与切页，再点结束停止。无需长按说话，不打开录音弹框，不出现未连接警告。以体验交互为目标，不宣称正在识别真实声音。
- **U67 文本确认与暂存**：转写／模拟文字可编辑，内容多时先在固定高度内滚动，主动点击展开才增高。发送、暂存、收起分别明确；停止说话本身不自动执行任务。暂存通过右侧便笺入口覆盖查看，保留原文及上下文；用户确认发送后再进入主会话并生成回执。
- **R54 真实能力后续接入**：真实语音识别、60 秒静音检测、断线恢复和语义整理属于后续能力验收；浏览器权限及异常反馈须在真实接入时设计，不能用模拟转写测试替代。当前普通发送与暂存已可演示，完整“整理—校对—确认”链路仍须逐项验证，不将 PRD 中目标能力直接视为全部实现。

## 5. 非功能需求

- **N1** 跨会话持久：事项、记忆在多次会话之间不丢失。
- **N2** 7×24 可运行，支持定时/周期/监控触发。
- **N3** 隐私安全：涉及家庭、健康、账户等信息需妥善保护；外部动作（下单/发消息）需授权确认。
- **N4** 多端可达：优先微信/企微等用户常驻渠道，另备 App/Web。

5. 其他风格主题与品牌统一后的适配；具体技术栈和集成边界继续由设计文档承接。
6. 未定启动时间任务的独立展示、优先事项聚合、实际无障碍对比度等，需对照本版规则专项验证。
